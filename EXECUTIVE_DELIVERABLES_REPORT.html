2. Critical Calculations & Accounting Glitches Resolved
Issue Description Root Cause Identified Engineering Solution Implemented
1. Receipt Disappearing Glitch
₹100 in history showed ₹0 on project & dashboard		 Receipts saved in Accounts were assigned status: 'confirmed', but project and dashboard filters strictly checked for 'received' or 'completed'. Updated financial query filters across Project Detail and Dashboard to recognize 'confirmed' receipts, immediately unlocking ₹100 into project metrics.
2. Dashboard vs P&L Contract Mismatch
Contract totals differed by ₹500		 Dashboard did not filter mid-project quotations by approved status and was gated only to MD, whereas P&L included approved variations (QTN-2 for ₹500). Standardized contract calculation across all screens to strictly use Base + Approved Quotations. Synchronized data access for both MD and Accounts.
3. Monthly Salary Over-Multiplication
₹30,000 salary became ₹45,000 for 1 Sunday shift		 Attendance system treated the ₹30,000 monthly rate as a daily wage rate, multiplying 1.5 days × ₹30,000 = ₹45,000 for a single 12-hour shift. Introduced getDailyWageRate() pro-rating monthly salaries on standard 30-day basis (₹1,000/day). A 1.5-day Sunday entry now computes to ₹1,500.
4. Historical Attendance Cost Mutation
Changing wage from ₹600 to ₹700 altered past weeks		 Attendance grids dynamically computed past wages using the employee's current master rate instead of locking historical wages. Attendance wages now sum historically locked calculated_wage and rec.wage_rate. Editing wage in Masters only affects future entries.
